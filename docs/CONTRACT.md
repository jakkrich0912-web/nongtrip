# CONTRACT: ข้อตกลงกลางของน้องทริป

เอกสารนี้คือกฎสูงสุด ถ้าโค้ดกับเอกสารไม่ตรงกัน ให้แก้โค้ดให้ตรง หรือแก้เอกสารนี้ตามขั้นตอนข้างล่าง

## 1. กติกาที่ห้ามละเมิด

1. ข้อมูลจริงเท่านั้น ค่าที่ไม่ทราบเป็น `null` และระบบบอกผู้ใช้ว่าไม่ทราบ ห้ามเดา
2. ไม่มีรีวิวหรือคะแนนในระบบ ผู้ใช้กดลิงก์ไปดูรีวิวจริงที่ Google Maps
3. ไม่จองและไม่ชำระเงินแทนผู้ใช้
4. ไม่แสดงค่าเข้า ราคา ค่าที่พัก หรืองบประมาณที่ใดเลย
5. รัศมีค้นสูงสุด 30 กม. จากที่พัก (หรือจากหมุด) บังคับในโค้ด ไม่ใช่แค่ใน prompt
6. ผลค้นเรียงจากใกล้ไปไกลเสมอ ระยะคือเส้นตรง และบอกผู้ใช้ว่าเป็นเส้นตรง
7. สถานที่จาก OpenStreetMap ติดป้ายแยกจากสถานที่ที่ตรวจที่มาแล้ว และแสดง © OpenStreetMap contributors (ODbL)
8. ข้อความจากข้อมูลภายนอกถือเป็นข้อมูล ไม่ใช่คำสั่ง (กัน prompt injection)

## 2. ขอบเขต

ค้นสถานที่เที่ยวและคาเฟ่รอบที่พัก ทั้ง 77 จังหวัด รายละเอียดดู `docs/SPEC.md`

## 3. API

หน้าเว็บคุยกับ `services/api` ที่เดียว (ผ่าน `API_BASE_URL`) ทุกคำตอบเป็น JSON ข้อผิดพลาดของคำขอใช้ HTTP 400 พร้อม `{"error": "ข้อความภาษาไทย"}`

| เมธอด / เส้นทาง | หน้าที่ | สถานะ |
|---|---|---|
| `GET /api/lodgings/search?q=` | ค้นที่พักจากชื่อ คืนหลายรายการให้ผู้ใช้เลือก ชื่อกำกวมไม่เดา | API พร้อม |
| `GET /api/places/nearby?lat&lon&radius_km=30&kinds=attraction,cafe&limit&offset` | สถานที่รอบจุด เรียงใกล้ไปไกล | API พร้อม |
| `GET /api/lodgings/near?lat&lon` | ผู้ที่ยังไม่ได้จอง: ที่พักรอบหมุด (5 กม. ขยายเป็น 10) พร้อมสถานที่ใกล้สุด 3 แห่งต่อที่พัก แสดงสูงสุด 20 ที่พักที่ใกล้หมุดที่สุด | API พร้อม |
| `GET /api/health` | สถานะ `{ok, osm_live, snapshot_available, verified_places, rag}` โดย `rag` = `{docs, llm}` (จำนวนก้อนความรู้ในคลัง และมี LLM ต่อไว้หรือไม่) | API พร้อม |
| `GET /api/provinces` | รายชื่อ 77 จังหวัดจัดตามภาค `{regions:[{region, provinces:[{name, verified_count}]}]}` ไว้ให้หน้าแรกเลือกจังหวัด | API พร้อม |
| `GET /api/provinces/{ชื่อ}/center` | จุดกลางจังหวัด `{province, region, lat, lon, source, notice?}` (`source` = `osm` หรือ `verified_centroid`; หาไม่ได้ `lat`/`lon` เป็น `null` และมี `notice`) | API พร้อม |
| `POST /api/chat` | แชต สตรีมผลทีละขั้น (SSE) เรียกเครื่องมือค้นตัวเดียวกับหน้าค้นหา ดูข้อ 3.2 | API พร้อม (โหมดกฎ หรือ LLM ถ้าต่อไว้) |
| `POST /api/auth/register`, `/login`, `/logout`, `GET /api/auth/me` | ผู้ใช้ (อีเมล+รหัสผ่าน แฮชแล้ว, คุกกี้เซสชัน) ดูข้อ 3.3 | API พร้อม |
| `GET /api/me/account`, `POST /api/me/password`, `POST /api/me/sessions/revoke-others` | ตั้งค่าบัญชี เปลี่ยนรหัสผ่าน ออกจากระบบอุปกรณ์อื่น ดูข้อ 3.3 | API พร้อม |
| `GET/POST/DELETE /api/me/searches`, `GET/POST/DELETE /api/me/favorites`, `GET/DELETE /api/me/chats` | ประวัติค้นที่พัก สถานที่โปรด ประวัติแชต (เฉพาะผู้ที่ล็อกอิน) ดูข้อ 3.4 | API พร้อม |
| `GET/POST/DELETE /api/me/searches`, `GET/POST/DELETE /api/me/favorites`, `GET/PATCH/DELETE /api/me/chats`, `PUT /api/me/chats/{id}/messages/{id}/rating` | ประวัติค้นที่พัก สถานที่โปรด ประวัติแชต (เฉพาะผู้ที่ล็อกอิน) ดูข้อ 3.4 | API พร้อม |

กฎของ `kinds`: ค่าที่รับคือ `attraction` และ `cafe` (ค่าเริ่มต้นทั้งสอง) ค่าอื่นถูกเมิน ถ้าไม่เหลือเลยตอบ 400

กฎของรัศมี: `radius_km` มากกว่า 0 และไม่เกิน 30 เกินแล้วตอบ 400 พิกัดนอกประเทศไทยตอบ 400

### 3.1 ข้อผิดพลาด

ทุก endpoint ที่พร้อมแล้วตอบข้อผิดพลาดแบบเดียวกัน: `{"error": "ข้อความภาษาไทย"}` ส่วน endpoint ผู้ใช้/ประวัติ (ข้อ 3.3-3.4) ใช้ HTTP code ตามตารางและมีฟิลด์ `code` เพิ่ม (เพิ่มอย่างเดียว ไม่ทำให้ฝั่งที่อ่านแค่ `error` พัง)

| HTTP | `code` | เมื่อไร | สถานะ |
|---|---|---|---|
| 400 | `invalid_param` | พารามิเตอร์ผิด รัศมีเกิน 30 กม. พิกัดนอกประเทศไทย | API พร้อม (endpoint ค้นหายังไม่ส่ง `code` ส่วน endpoint ผู้ใช้ส่ง) |
| 401 | `unauthorized` | ยังไม่ล็อกอิน หรืออีเมล/รหัสผ่านไม่ถูกต้อง | API พร้อม |
| 404 | `not_found` | ไม่พบแชต (รวมถึงแชตของผู้อื่น) ทั้งตอนอ่าน ลบ และส่งต่อแชตเดิมด้วย `chat_id` | API พร้อม |
| 409 | `email_taken` | สมัครด้วยอีเมลที่มีแล้ว | API พร้อม |
| 429 | `rate_limited` | ใส่รหัสผ่านผิดครบ 5 ครั้งใน 5 นาทีต่ออีเมล สมัครเกิน 20 ครั้งต่อ IP ต่อชั่วโมง หรือส่งแชตเกิน `CHAT_RATE_PER_MIN` (ค่าเริ่มต้น 20) ต่อ IP ต่อนาที | API พร้อม |
| 501 | `google_not_configured` | ยังไม่ตั้ง `GOOGLE_CLIENT_ID` จึงยังไม่เปิดล็อกอินด้วย Google | API พร้อม |
| 502 | `upstream_unavailable` | บริการภายนอกล่มและไม่มีสแนปช็อต หรือติดต่อ Google ตอนล็อกอินไม่ได้ | ล็อกอิน Google พร้อม ส่วนค้นหายังวางแผน |

### 3.2 แชต (API พร้อม โหมดกฎ และโหมด LLM เมื่อตั้งค่าไว้)

`POST /api/chat` ส่ง `{"message": "...", "context": {"lat": 18.79, "lon": 98.98}, "chat_id": 12, "last_province": "น่าน", "lang": "en"}` ตอบเป็น Server-Sent Events (`text/event-stream`)

| ฟิลด์ | กติกา |
|---|---|
| `message` | บังคับ 1-500 ตัวอักษร (ตัดอักขระควบคุมและช่องว่างซ้ำ ข้อความว่างตอบ 400) |
| `context` | ไม่บังคับ พิกัดหมุด/ที่พักที่ผู้ใช้เลือกไว้ ต้องอยู่ในไทย ไม่งั้น 400 |
| `chat_id` | ไม่บังคับ ต่อแชตเดิมของผู้ที่ล็อกอิน ไม่พบหรือเป็นของคนอื่นตอบ 404 ผู้ที่ไม่ล็อกอินเมิน |
| `last_province` | ไม่บังคับ (v0.15) จังหวัดที่ถามไว้ล่าสุด หน้าเว็บจำจาก `done.province` ใช้เฉพาะเมื่อข้อความใหม่ไม่ระบุจังหวัด ไม่มีหมุด `context` และไม่มีชื่อที่พัก (เช่น "แล้วคาเฟ่ล่ะ") ชื่อที่ไม่ใช่หนึ่งใน 77 จังหวัดถูกเมิน |
| `edit_from` | ไม่บังคับ (v0.21) ต้องล็อกอินและส่ง `chat_id` ด้วย รหัสข้อความของผู้ใช้ในแชตนั้น (`done.user_message_id` หรือ `messages[].id`) ลบข้อความตั้งแต่ข้อความนั้นลงไปแล้วถามด้วย `message` ใหม่ ใช้แก้คำถามและถามใหม่ ไม่ใช่ข้อความผู้ใช้ในแชตของฉัน ตอบ 404 |
| `history` | ไม่บังคับ (v0.24) บทสนทนาก่อนหน้าในแชตเดียวกัน `[{"role": "user" \| "assistant", "content": "..."}]` เรียงเก่าไปใหม่ ไม่เกิน 20 รายการ แต่ละข้อความไม่เกิน 4000 ตัวอักษร (ผิดรูปแบบตอบ 400) ระบบใช้ไม่เกิน 6 ข้อความท้าย ตัดข้อความละ 400 ตัวอักษร ใส่ในพรอมต์ของโหมด LLM เป็นบล็อก `<history>` ไว้เข้าใจคำถามต่อเนื่องเท่านั้น (ห้ามใช้เป็นแหล่งข้อมูล ด่านตรวจเหมือนเดิม) และใช้ค้นคลังความรู้รวมกับคำถามก่อนหน้าเมื่อคำถามล่าสุดค้นไม่เจอ ไม่บันทึกเพิ่มจากที่บันทึกอยู่แล้ว โหมดกฎไม่ใช้ |
| `lang` | ไม่บังคับ `th` (ค่าเริ่มต้น) หรือ `en` (v0.15) เลือกภาษาของคำตอบ: ข้อความสำเร็จรูปและหมายเหตุจากบริการค้นถูกแปลเป็นอังกฤษ ชื่อสถานที่ใช้ `name_en` ถ้ามี ชื่อจังหวัดเป็นอังกฤษ (v0.16) โหมด LLM ใช้พรอมต์ภาษาอังกฤษและด่านตรวจคาดหวังคำตอบเป็นอังกฤษ (กฎอื่นเหมือนเดิม) ตัวทำความเข้าใจข้อความเข้าใจทั้งไทยและอังกฤษเสมอ ไม่ขึ้นกับ `lang` (v0.16) |

บอทไม่เก็บสถานะระหว่างคำขอ หน้าเว็บเป็นคนส่งบริบทมาทุกครั้ง: `context` เมื่อมีหมุด `last_province` ถ้าเคยถามจังหวัดไว้ และ `history` เป็นบทสนทนาก่อนหน้า (v0.24) หน้าเว็บเก็บแชตที่คุยอยู่ไว้ใน sessionStorage ของแท็บ เปลี่ยนหน้าหรือรีเฟรชแล้วยังอยู่ ปิดแท็บแล้วหายไป

ลำดับ event ทีละขั้น:

| event | data | ความหมาย |
|---|---|---|
| `tool` | `{"name": "places_nearby", "args": {...}}` | กำลังเรียกเครื่องมือค้น ชื่อที่เป็นไปได้: `province_center`, `lodgings_search`, `lodgings_near`, `places_nearby` |
| `places` | `{"items": [...], "validation": {...}, "notices": [...], "center", "radius_km", "total", "counts", "sources", "osm_mode", "osm_available", "attribution", "distance_note"}` | ผลค้นสถานที่ที่ผ่านตัวตรวจแล้ว หน้าเว็บแสดงเป็นการ์ด ถ้าตัวตรวจไม่ผ่าน `items` เป็น `[]` และมีข้อความเตือนใน `notices` |
| `lodgings` | `{"source": "search" \| "near", "items": [...], "notices": [...], ...}` | `search` = ผลค้นชื่อที่พัก (รูปแบบเดียวกับ `/api/lodgings/search`) `near` = ที่พักรอบหมุด (รูปแบบเดียวกับ `/api/lodgings/near`) |
| `sources` | `{"items": [{"id", "place_id", "title", "url", "license", "checked_on"}]}` | **v0.13** ส่งก่อน `token` เฉพาะโหมด LLM บอกก้อนความรู้ที่คำตอบอ้าง (รหัส `id` ตรงกับ `[k:...]` ในข้อความ) หน้าเว็บต้องแสดงที่มาและสัญญาอนุญาตจาก `license`/`url` โหมดกฎไม่ส่ง event นี้ |
| `token` | `{"text": "..."}` | ข้อความตอบทีละบรรทัด (ลงท้ายด้วย `\n`) |
| `done` | `{"chat_id": 12, "mode": "rule" \| "llm"}` | จบ `chat_id` เป็น `null` ถ้าไม่ได้ล็อกอิน (ไม่บันทึก) `mode` (v0.13) บอกว่าคำตอบนี้มาจากโหมดไหน ใช้แสดงป้ายโหมด `province` (v0.15 มีเฉพาะเมื่อคำตอบนี้ค้นรอบจังหวัดนั้น) ให้หน้าเว็บจำไว้ส่งเป็น `last_province` `ask` (v0.17 มีเมื่อคำตอบถามกลับ ตอนนี้มีค่าเดียวคือ `"location"` = ยังไม่รู้ว่าให้ค้นแถวไหน มีในโหมดกฎ และตั้งแต่ v0.25 ในคำตอบเรื่องเที่ยวทั่วไปของโหมด LLM ที่ไม่มีรายชื่อสถานที่ด้วย) หน้าเว็บใช้แสดงปุ่มเลือกตำแหน่ง/จังหวัด ไม่มีฟิลด์นี้ก็ทำงานได้ `message_id` และ `user_message_id` (v0.21 มีเฉพาะเมื่อล็อกอินและบันทึกสำเร็จ) รหัสคำตอบและคำถามรอบนี้ ใช้ให้คะแนนและแก้คำถาม |
| `error` | `{"error": "...", "code": "invalid_param" \| "internal"}` | ผิดพลาดระหว่างสตรีม (HTTP ยังเป็น 200) ไม่ส่ง `done` |

ถ้าคำขอผิดก่อนเริ่มสตรีม ตอบ HTTP 400/404/429 เป็น JSON ตามข้อ 3.1

**โหมด LLM (v0.13):** เปิดเมื่อตั้ง `LLM_PROVIDER` (anthropic/openai) พร้อมคีย์และ `LLM_MODEL` ใน `.env` และมีคลังความรู้ ลำดับคือ ค้นด้วยเครื่องมือและตัวตรวจเดิมก่อน (`places` ผ่านตัวตรวจแล้ว) > ค้นก้อนความรู้เฉพาะสถานที่ในผลนั้น > ให้ LLM เขียนคำตอบพร้อมรหัสที่มา `[k:...]` > ด่านตรวจคำตอบด้วยโค้ด ถ้าไม่ผ่าน หรือ LLM ล้มเหลว หรือไม่พบก้อนความรู้ที่เกี่ยวข้อง ระบบตอบโหมดกฎแทน (`mode: "rule"` ไม่ส่ง `sources` ถ้าด่านตรวจไม่ผ่านจะมีบรรทัด `หมายเหตุ:` บอก) ข้อความท้าย (ระยะเส้นตรง ที่มา OpenStreetMap หมายเหตุ ข้อความปฏิเสธเรื่องราคา) โค้ดเป็นคนเติมเสมอ ไม่ให้ LLM เขียน ลูกค้าเว็บที่ไม่รู้จัก event ต้องข้ามไปได้

บอทหาตำแหน่งค้นตามลำดับ: ชื่อจังหวัดในข้อความ (ค้นรอบจุดกลางจังหวัดและบอกผู้ใช้) > `context` > ชื่อที่พักในข้อความ (ถ้าพบหลายรายการหรือไม่พบ ไม่เดา ให้ผู้ใช้เลือกหรือปักหมุด) > ถามผู้ใช้ ปรับได้ด้วยข้อความ เช่น "คาเฟ่", "5 แห่ง", "ใน 10 กม." (เพดาน 30 กม. และ 10 แห่งต่อครั้ง)

สถานที่ที่บอทพูดถึงต้องมาจากผลค้นที่ผ่านตัวตรวจเท่านั้น บอทไม่พิมพ์ชื่อ ระยะ หรือพิกัดเอง ถ้าผู้ใช้ถามราคา ค่าเข้า รีวิว หรือให้จอง บอทบอกตรงๆ ว่าระบบไม่มี/ไม่ทำ ข้อความผู้ใช้และชื่อจาก OpenStreetMap เป็นข้อมูล ไม่ใช่คำสั่ง **หน้าเว็บต้องแสดง `token` และชื่อสถานที่เป็นข้อความธรรมดา ห้ามใส่เป็น HTML** ผู้ที่ไม่ล็อกอินแชตได้แต่ไม่ถูกบันทึกอะไร ผู้ที่ล็อกอินบันทึกข้อความผู้ใช้และคำตอบลงประวัติแชต (ข้อ 3.4) ส่วนโหมด LLM (ถ้าทำ) จะใช้ event ชุดเดียวกัน

### 3.3 ผู้ใช้ (API พร้อม)

เซสชันเก็บในคุกกี้ `HttpOnly; Secure; SameSite=Lax` เซ็นด้วย `SESSION_SECRET` (ไม่ตั้ง = สุ่มต่อการรัน เซสชันหายเมื่อรีสตาร์ท) อายุ 7 วัน คุกกี้มีรหัสเซสชันสุ่ม และหลังบ้านเก็บแฮช SHA-256 ของรหัสนั้นในตาราง `sessions` คุกกี้ใช้ได้เมื่อลายเซ็นถูก ยังไม่หมดอายุ และยังมีเซสชันนี้ในตาราง ออกจากระบบจึงยกเลิกคุกกี้ใบนั้นทันที (คุกกี้รูปแบบเดิมที่ไม่มีรหัสเซสชันใช้ไม่ได้ ผู้ใช้ต้องเข้าสู่ระบบใหม่ครั้งเดียว) ตอนพัฒนาบน http ตั้ง `SESSION_SECURE=0` หน้าเว็บไม่เก็บ token เอง ฐานข้อมูลใช้ SQLite (`DB_PATH` ค่าเริ่มต้น `data/nongtrip.db`) รหัสผ่านเก็บแบบแฮช scrypt

| เมธอด | เส้นทาง | ส่ง | ตอบ |
|---|---|---|---|
| POST | `/api/auth/register` | `{"email", "password"}` รหัสผ่าน 8-200 ตัว อีเมลไม่สนตัวพิมพ์ใหญ่เล็ก | `201 {"user": {"id", "email"}}` และล็อกอินให้ทันที (ตั้งคุกกี้) `409 email_taken` `429 rate_limited` (สมัครเกิน 20 ครั้งต่อ IP ต่อชั่วโมง) |
| POST | `/api/auth/login` | `{"email", "password"}` | `200 {"user": {...}}` ผิดตอบ `401` (ไม่บอกว่าผิดอีเมลหรือรหัส) |
| POST | `/api/auth/logout` | - | `204` ยกเลิกเซสชันของคุกกี้นี้ในฐานข้อมูลด้วย อุปกรณ์อื่นยังเข้าสู่ระบบอยู่ |
| GET | `/api/auth/me` | - | `200 {"user": {...}}` หรือ `401` |
| POST | `/api/auth/google` | `{"credential": "<Google ID token>"}` (1-5000 ตัวอักษร) | `201 {"user": {...}}` เข้าครั้งแรก (สร้างบัญชีให้) `200` เข้าซ้ำ แล้วตั้งคุกกี้เซสชันเหมือนล็อกอินปกติ `401` token ใช้ไม่ได้ `409 email_taken` `429 rate_limited` `501 google_not_configured` `502 upstream_unavailable` |
| GET | `/api/me/account` | - ต้องล็อกอิน | `200 {"email", "created_at", "has_password", "google", "sessions"}` `has_password` = เข้าด้วยรหัสผ่านได้ `google` = ผูกกับบัญชี Google `sessions` = จำนวนเซสชันที่ยังไม่หมดอายุ (รวมเครื่องนี้) ไม่ส่งค่าแฮชรหัสผ่าน `401` ถ้าไม่ได้ล็อกอิน |
| POST | `/api/me/password` | `{"current_password", "new_password"}` ต้องล็อกอิน | `200 {"signed_out": <จำนวนเซสชันอื่นที่ถูกยกเลิก>}` เปลี่ยนรหัสผ่าน ยกเลิกทุกเซสชันเดิม แล้วตั้งคุกกี้ใหม่ให้เครื่องนี้ `400 wrong_password` รหัสปัจจุบันผิด (นับรวมกับตัวจำกัดของหน้าเข้าสู่ระบบ) `400 invalid_param` รหัสใหม่ไม่ใช่ 8-200 ตัว หรือซ้ำรหัสเดิม `400 no_password` บัญชี Google `429 rate_limited` `401` |
| POST | `/api/me/sessions/revoke-others` | - ต้องล็อกอิน | `200 {"signed_out": <จำนวน>}` ออกจากระบบทุกอุปกรณ์ยกเว้นเครื่องนี้ `401` |
| POST | `/api/me/delete` | `{"email": "<อีเมลของตัวเอง>"}` ต้องล็อกอิน | `204` ลบบัญชีและข้อมูลทั้งหมดของผู้ใช้ถาวร (ที่พักที่ค้น สถานที่โปรด แชตและข้อความ) แล้วล้างคุกกี้เซสชัน `400 invalid_param` ถ้าอีเมลไม่ตรงกับบัญชี (ไม่สนตัวพิมพ์ใหญ่เล็กและช่องว่างหัวท้าย) `401` ถ้าไม่ได้ล็อกอิน บัญชี Google ลบได้เหมือนกัน ลบแล้วสมัครอีเมลเดิมใหม่ได้ เป็นบัญชีใหม่ไม่มีข้อมูลเก่า |

**ล็อกอินด้วย Google:** หน้าเว็บใช้ Google Identity Services ขอ ID token แล้วส่งมาที่ `/api/auth/google` (ต้องมี `GOOGLE_CLIENT_ID` ที่สร้างใน Google Cloud Console และใส่ที่มาของเว็บใน Authorized JavaScript origins) หลังบ้านให้ Google ตรวจลายเซ็น แล้วตรวจเองว่า `aud` ตรงกับ `GOOGLE_CLIENT_ID` ของเรา, `iss` เป็น Google, ยังไม่หมดอายุ และอีเมลผ่านการยืนยันแล้ว บัญชี Google ใช้ `sub` เป็นตัวระบุ (เปลี่ยนอีเมลที่ Google ก็ยังเป็นคนเดิม) ไม่มีรหัสผ่านจึงล็อกอินด้วยอีเมล/รหัสผ่านไม่ได้ **ถ้าอีเมลนั้นสมัครด้วยรหัสผ่านไว้แล้ว ตอบ 409 และไม่ผูกให้เอง** เพราะตอนสมัครด้วยรหัสผ่านเรายังไม่ยืนยันอีเมล (ถ้าผูกให้ ผู้ที่สมัครอีเมลของคนอื่นไว้ล่วงหน้าจะเข้าบัญชีเดียวกับเจ้าของอีเมลได้) ตัวจำกัด: 30 คำขอต่อ IP ต่อนาที (กันถูกใช้ยิง Google)

ผู้ที่ไม่ได้ล็อกอินไม่ถูกบันทึกอะไรเลย (ทั้งประวัติ สถานที่โปรด และแชต)

### 3.6 แดชบอร์ดผู้ดูแล (API พร้อม เฉพาะผู้ดูแล)

ผู้ดูแลคือบัญชีที่อีเมลอยู่ใน `ADMIN_EMAILS` (คั่นด้วยจุลภาค ไม่สนตัวพิมพ์) ทุกคำตอบที่มี `user` (register, login, google, me) มีฟิลด์ `is_admin` เพิ่ม หน้าเว็บใช้ซ่อนหรือแสดงลิงก์แดชบอร์ด

| เมธอด | เส้นทาง | ตอบ |
|---|---|---|
| GET | `/api/admin/overview` | `200` ยอดรวมของทั้งระบบ: `system` (LLM เปิดอยู่ไหม จำนวนก้อนความรู้ สถานที่ที่ตรวจแล้ว OSM สด วันที่ดึงสแนปช็อต) `users` (จำนวนบัญชี บัญชี Google สมัครใหม่ 7 วัน ผู้ที่เข้าอยู่ เซสชัน) `content` (ที่พักที่บันทึก สถานที่โปรด แชต ข้อความ) `ratings` (`{up, down}` หรือ `null` ถ้ายังไม่มีการให้คะแนน) `top_favorites` (เฉพาะสถานที่ที่บันทึกตั้งแต่ 2 บัญชีขึ้นไป) `usage` (กราฟรายวัน 14 วัน และยอด 30 วัน: แชตแยกโหมด สาเหตุที่ด่านตรวจตีตก จำนวนการค้น จังหวัดที่ค้นบ่อย หน้าจังหวัดที่เปิดบ่อย) `coverage` (รายจังหวัด: จำนวนสถานที่ที่ตรวจแล้ว มีสแนปช็อตหรือไม่) `401` ไม่ได้ล็อกอิน `403 forbidden` ไม่ใช่ผู้ดูแล |

ตัวนับเก็บในตาราง `metrics` เป็นแถว (วัน ชนิด ค่า จำนวน) เท่านั้น วันนับตามเวลาประเทศไทย (UTC+7) ไม่มีข้อความ IP หรือรหัสผู้ใช้ นับ: การค้นรอบจุด (ไม่นับตอนโหลดเพิ่ม) การปักหมุดหาที่พัก จังหวัดของจุดค้น (ประมาณจากสถานที่ที่ตรวจแล้วที่ใกล้ที่สุดในรัศมี 60 กม.) การเปิดหน้าจังหวัด โหมดของคำตอบแชต และกฎของด่านตรวจที่ไม่ผ่าน นับไม่สำเร็จไม่ทำให้คำขอล้ม

### 3.5 ไกด์ที่เที่ยว (API พร้อม ไม่ต้องล็อกอิน)

ใช้กับหน้าแรก หน้าจังหวัด และหน้ารายละเอียดสถานที่ ข้อมูลมาจากสถานที่ที่ **ตรวจที่มาแล้วเท่านั้น** (`verified=true`) ไม่มีราคา ค่าเข้า คะแนน หรือรีวิว ฟิลด์ที่ไม่มีแหล่งอ้างอิงเป็น `null` หรือ `[]` หน้าเว็บต้องซ่อนส่วนนั้นเลย ห้ามเติมเอง สถานที่จาก OpenStreetMap ไม่มีหน้ารายละเอียด

| เมธอด | เส้นทาง | ตอบ |
|---|---|---|
| GET | `/api/guide/featured?limit=12&category=` | `{items:[สถานที่], categories:{temple: 92, ...}, total}` จังหวัดละ 1 แห่ง (ถ้าจังหวัดนั้นมีคำอธิบายจะเลือกแห่งที่มี) สลับไปทีละภาค **ไม่ใช่การจัดอันดับความนิยม** (ระบบไม่มีข้อมูลนั้น) `limit` 1-50 |
| GET | `/api/provinces/{ชื่อ}/places?category=&limit=50&offset=0` | `{province, region, verified_count, categories, total, items, has_more}` จังหวัดที่ยังไม่มีข้อมูลตอบ `verified_count: 0` และ `items: []` (ไม่ใช่ข้อผิดพลาด) ชื่อจังหวัดผิดตอบ `400 invalid_param` `limit` 1-200 `verified_count` ไม่ขึ้นกับ `category` |
| GET | `/api/places/{id}` | สถานที่ 1 แห่ง (`id` แบบ `v:p01`) ไม่พบ หรือเป็นรหัส `osm:` ตอบ `404 not_found` |

รูปสถานที่ในไกด์: `{id, name_th, name_en, kind, subtype, province, area, description, notes[], lat, lon, maps_url, source_url, source_title, source_checked_on}` `subtype` ตอนนี้มี `temple` `nature` `museum` `activity` `market` `cafe` `craft` (หน้าเว็บเป็นคนแปลงเป็นป้ายภาษาไทย) `area` เป็น `null` เมื่อไม่มีข้อมูลย่านแยกจากจังหวัด `description` ตอนนี้ยังมีไม่กี่แห่ง ต้องมีแหล่งอ้างอิงก่อนจึงเติมได้ (กติกาข้อ 1) `source_*` คือแหล่งที่ตรวจพิกัด/ชื่อ แสดงเป็น "ที่มาของข้อมูล" ได้

## 4. รูปแบบข้อมูล

### สถานที่ (`items[]` ของ `nearby` และ `nearest[]` ของ `lodgings/near`)

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | `v:<id>` = ตรวจที่มาแล้ว, `osm:<node\|way\|relation>/<เลข>` = จาก OpenStreetMap |
| `name_th`, `name_en` | ชื่อ (`name_en` เป็น `null` ได้) |
| `kind` | `attraction` หรือ `cafe` |
| `subtype` | ประเภทย่อย เช่น `temple`, `waterfall`, `viewpoint`, `cafe` |
| `lat`, `lon` | พิกัด |
| `distance_km` | ระยะเส้นตรงจากจุดค้น ปัด 2 ตำแหน่ง |
| `source` | `verified` หรือ `osm` (หน้าเว็บต้องติดป้ายแยกกัน) |
| `province`, `source_url` | จังหวัด / ลิงก์แหล่งที่มา (ไม่ทราบเป็น `null`) |
| `maps_url` | เปิดหน้าสถานที่บน Google Maps (ไว้ดูรีวิว) |
| `directions_url` | ปุ่ม "นำทางด้วย Google Maps" จากจุดค้นไปสถานที่ |

ไม่มีฟิลด์ราคา ค่าเข้า คะแนน หรือรีวิวในคำตอบใดทั้งสิ้น

### คำตอบของ `places/nearby`

`center`, `osm_mode` (`live` = ดึงออนไลน์, `snapshot` = ใช้ข้อมูล OSM ที่ดึงไว้ล่วงหน้า, `none` = ไม่มีข้อมูล OSM เลย), `radius_km` (รัศมีที่ใช้จริง อาจน้อยกว่าที่ขอ ถ้าพื้นที่หนาแน่นจน OSM ส่งไม่ไหว), `total`, `offset`, `limit`, `counts` (ต่อ kind), `sources` (`verified`/`osm`), `osm_available`, `notices[]` (ข้อความภาษาไทยที่หน้าเว็บต้องแสดง), `attribution`, `distance_note`, `items[]`

ถ้าเชื่อม OSM ออนไลน์ไม่ได้ ระบบใช้สแนปช็อต (`osm_mode=snapshot`, `osm_available=true`) **v0.14:** โหมดนี้ไม่ใส่ข้อความเตือนว่าใช้ข้อมูลที่บันทึกไว้ใน `notices` อีก (ไคลเอนต์ดูได้จาก `osm_mode`) ถ้าไม่มีสแนปช็อตด้วย `osm_available=false`, `osm_mode=none` ระบบแสดงเฉพาะ `verified` และใส่ข้อความใน `notices` ที่หน้าเว็บต้องแสดง

`validation` (ทั้ง `nearby` และ `lodgings/near`): ผลของตัวตรวจอิสระ `{ok, checked, problems[], problem_count}` ตรวจรัศมี ≤ 30 กม. เรียงใกล้ไปไกล ไม่ซ้ำ ไม่มีเงิน/คะแนน/รีวิว ป้ายแหล่งข้อมูล และสถานที่ที่ตรวจแล้วมีอยู่จริงในไฟล์ข้อมูล ถ้า `ok=false` API เพิ่มข้อความเตือนใน `notices` และหน้าเว็บต้องแสดงป้ายเตือน

`GET /api/lodgings/search?q=<ชื่อ>&province=&area=&subtype=` (`maps_url` ในตัวอย่างข้างบนย่อไว้ ค่าจริงเป็น URL ที่เข้ารหัสแล้ว)

ตัวกรองไม่บังคับ ใช้แยกที่พักชื่อซ้ำ ทุกตัวต้องตรงพร้อมกัน: `province` ต้องเป็นหนึ่งใน 77 จังหวัด, `area` คือย่าน/อำเภอ/ถนน (ข้อความที่ปรากฏในที่อยู่ ไม่เกิน 100 ตัว), `subtype` ต้องเป็น `hotel` `guest_house` `hostel` `motel` `resort` `apartment` `chalet` ค่าผิดตอบ `400` รายการที่ไม่รู้จังหวัดจะถูกตัดออกเมื่อขอกรองจังหวัด (ไม่เดาให้) ตัวอย่างรายการมีฟิลด์ `province` เพิ่ม (`null` ถ้าไม่รู้) โหมด `osm_mode: snapshot` กรองย่านไม่ได้ และจะบอกใน `notices` ผลค้นที่พบหลายรายการยังขึ้นข้อความให้เลือกเหมือนเดิม หน้าเว็บต้องให้ผู้ใช้เลือกเองเสมอ ห้ามเลือกแห่งแรกให้

```json
{
  "items": [{"id": "osm:way/123456", "name": "โรงแรมตัวอย่าง", "address": null,
             "subtype": "hotel", "lat": 18.79, "lon": 98.98, "province": "เชียงใหม่"}],
  "osm_available": true,
  "osm_mode": "live",
  "notices": []
}
```

ไม่พบตอบ `200` กับ `items: []` ชื่อกำกวมคืนหลายรายการให้ผู้ใช้เลือก

### คำตอบของ `lodgings/search`

`items[]` ของ `{id, name, address, subtype, lat, lon}` (ที่พักจริงขึ้นก่อน), `osm_available`, `osm_mode`, `notices[]`

### คำตอบของ `lodgings/near`

เพิ่ม `lodgings_total` (จำนวนที่พักที่พบทั้งหมด ถ้ามากกว่า 20 จะแสดง 20 แห่งที่ใกล้หมุดที่สุดและมีข้อความใน `notices`)

`radius_km` (ที่ใช้จริง 5 หรือ 10), `items[]` ของที่พัก: `{id, name, subtype, lat, lon, distance_from_pin_km, maps_url, places_radius_km, places_total, counts, nearest[], has_more}`, `osm_available`, `notices[]`, `attribution`

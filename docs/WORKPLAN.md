## สิ่งที่ต้องทำต่อ แยกตามคน

**Jakkrich**

1. รีวิว PR #1 ของ Jirapa หลังเธอแก้ แล้วต่อหน้าค้นหาและหน้าแชตกับ API จริง
2. ตรวจผลสแนปช็อต OSM ทั้งประเทศ แล้ว commit ผ่าน PR
3. ผลวัด และซ้อมบนอินเทอร์เน็ตจริง วิดีโอสำรอง

**Jirapa**

1. รีเซ็ต `develop` ในเครื่อง (`git fetch origin` แล้ว `git reset --hard origin/develop`) เพราะประวัติถูกเขียนใหม่
2. PR #1: เปลี่ยน base เป็น `develop`, merge `develop` เข้าสาขา, แก้ตามคอมเมนต์รีวิว 4 ข้อ (ชื่อ endpoint ใน `api.js`, อ่านข้อความผิดพลาดจากฟิลด์ `error`, kind/subtype ให้ตรงสัญญา, ดึง develop ล่าสุด) และปิด PR #2
3. หน้าล็อกอิน/สมัคร และหน้าประวัติ/สถานที่โปรด ต่อกับ API v0.7 (ตั้ง `SESSION_SECURE=0` ใน `.env` ตอนพัฒนาบน http; ผู้ที่ไม่ล็อกอินได้ 401 ให้ซ่อนปุ่มบันทึก)
4. ข้อมูลที่ตรวจแล้วที่เหลือ และชุดทดสอบ 10-15 จังหวัด
5. สไลด์และ DEMO_SCRIPT
6. หน้าเพิ่มตามแบบร่างบนคอนเวิร์ส (บอร์ด 6-11) ต่อ API ตาม CONTRACT v0.11: เลือกที่พัก (ใช้ `/api/lodgings/search` พร้อมตัวกรอง ต้องให้ผู้ใช้เลือกเอง ห้ามเลือกแห่งแรกให้), ที่พักรอบหมุด (`/api/lodgings/near`), รายละเอียดสถานที่ (`/api/places/{id}`), หน้าจังหวัด (`/api/provinces/{ชื่อ}/places`), หน้าแรกส่วนไกด์ (`/api/guide/featured`), ที่มาของข้อมูล, หน้าข้อผิดพลาด ข้อความแจ้งเตือน (`notices`) แสดงเป็นแถบข้อความธรรมดาเฉพาะตอนมี ห้ามมีกล่องว่างค้างและห้ามเอ่ยคำว่า API
7. ปุ่มล็อกอินด้วย Google: ใช้ Google Identity Services ขอ ID token แล้วส่ง `{"credential"}` ไป `POST /api/auth/google` (ได้ 409 ให้บอกผู้ใช้ให้ล็อกอินด้วยรหัสผ่าน, 501 ให้ซ่อนปุ่ม)
8. ไกด์ที่เที่ยว: ตอนนี้ `description` มี 11 จาก 326 แห่ง ถ้าเติมต้องมีแหล่งอ้างอิงในไฟล์ข้อมูล รูปสถานที่ต้องเป็นรูปที่มีสิทธิ์ใช้พร้อมเครดิต

## ลำดับพึ่งพา

1. หน้าเว็บเรียก API ผ่านค่าตั้ง `API_BASE_URL` เดียว ใช้ข้อมูลตัวอย่างตอนที่ API ยังไม่พร้อม แล้วสลับมาเรียกของจริง
2. ตัวตรวจ (validator) เขียนแยกจากบริการค้นหา ห้ามใช้โค้ดค้นหาร่วมกัน
3. หน้าล็อกอินและหน้าประวัติต้องรอ PR #1 merge ก่อน ส่วนแชตบอทฝั่ง API ไม่ต้องรอใคร
